# Compatibility

## Supported runtime

| Component | Version | Verified by |
|---|---|---|
| Node.js (everything, ESM + CJS) | 20.19+, 22, 24 | CI `smoke` job installs the packed tarball on each version; CI `test` job runs the end-to-end proof suite on each |
| Node.js 18 | **not supported** | `@iden3/js-crypto` fails on import (no global `crypto`, ESM build) and `@noble/hashes@2` requires Node ≥ 20.19. This was already the case for 0.1.x; the `engines` field previously over-promised. |
| Browsers / bundlers | tree, input and ABI helpers only (no Node built-ins); proving is Node-only | `attw` + `publint` in CI |
| Module formats | ESM (`import`) and CommonJS (`require`), with types for both | `attw --profile node16` in CI |

## Circuit toolchain

Circuit artifacts are **not** bundled; compile them from [zk-smart-account-kit](https://github.com/MicrochainLabs/zk-smart-account-kit).

| SDK | Nargo / `@noir-lang/noir_js` | `@aztec/bb.js` (peer) | Circuits |
|---|---|---|---|
| 0.1.x | `1.0.0-beta.22` | `5.0.0-nightly.20260522` (exact) | `zk_signers`, `zk_label_binding`, `zk_scope_validation` |

### Why the peers are pinned

- `@noir-lang/noir_js` must match the Nargo version that compiled the circuit (ACIR format).
- `@aztec/bb.js` produces the proofs that the on-chain `HonkVerifier` checks; the verifier contract and the prover must come from the same Barretenberg generation. Upgrading the pin is a **circuits + verifier redeploy** decision, not a routine bump (Dependabot ignores both packages for this reason).
- A nightly is pinned because that is what the deployed verifiers were generated with. Move to a stable release together with the circuits.

### Latest stable `@aztec/bb.js`

CI runs an informational job (`compat-bb-latest`) that executes the full end-to-end suite — prove **and** verify, off-chain — against the latest stable `@aztec/bb.js`. At the time of writing `5.3.0` passes. That does **not** establish that proofs verify against a verifier contract generated by a different Barretenberg release; confirm on-chain before changing the pin.

## Refreshing circuit fixtures

The end-to-end tests use stripped copies of the compiled circuits in `test/fixtures/circuits/`:

```bash
# after recompiling circuits in zk-smart-account-kit
pnpm sync-circuits ../zk-smart-account-kit/noir/target
pnpm test
```

`manifest.json` records the Noir version and a SHA-256 per artifact so circuit changes are visible in review.
