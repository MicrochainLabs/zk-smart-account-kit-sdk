# Compatibility

## Supported runtime

| Component | Version | Verified by |
|---|---|---|
| Node.js (everything, ESM + CJS) | 20.19+, 22, 24 | CI `smoke` job installs the packed tarball on each version; CI `test` job runs the end-to-end proof suite on each |
| Node.js 18 | **not supported** | `@iden3/js-crypto` fails on import (no global `crypto`, ESM build) and `@noble/hashes@2` requires Node ≥ 20.19. This was already the case for 0.1.x; the `engines` field previously over-promised. |
| Browsers / bundlers | tree, input and ABI helpers only (no Node built-ins); proving is Node-only | `attw` + `publint` in CI |
| Module formats | ESM (`import`) and CommonJS (`require`), with types for both | `attw --profile node16` in CI |

## Circuit toolchain

Circuit artifacts are **not** bundled; compile them from [zk-smart-account-kit](https://github.com/MicrochainLabs/zk-smart-account-kit).

| SDK | Nargo / `@noir-lang/noir_js` | `@aztec/bb.js` (peer) | Circuits |
|---|---|---|---|
| 0.1.x | `1.0.0-beta.22` | `5.0.0-nightly.20260522` (exact) | `zk_signers`, `zk_label_binding`, `zk_scope_validation` |

### Why the peers are pinned

- `@noir-lang/noir_js` must match the Nargo version that compiled the circuit (ACIR format).
- `@aztec/bb.js` produces the proofs that the on-chain `HonkVerifier` checks; the verifier contract and the prover must come from the same Barretenberg generation. Upgrading the pin is a **circuits + verifier redeploy** decision, not a routine bump (Dependabot ignores both packages for this reason).
- A nightly is pinned because that is what the deployed verifiers were generated with. Move to a stable release together with the circuits.

### Latest stable `@aztec/bb.js`

CI runs an informational job (`compat-bb-latest`) that executes the full end-to-end suite — prove **and** verify, off-chain — against the latest stable `@aztec/bb.js`. At the time of writing `5.3.0` passes. That does **not** establish that proofs verify against a verifier contract generated by a different Barretenberg release; confirm on-chain before changing the pin.

## Contracts

The ZK MultiSig integrations (`zk-multisig/safe`, `zk-multisig/nexus`) talk to the contracts of [microchain-zk-signers](https://github.com/MicrochainLabs/microchain-zk-signers). Their ABIs are checked in the test suite against the compiled contracts.

| Contract | Version tested against |
|---|---|
| `ZKMultiSigEcdsaFactory`, `ZKMultiSigEcdsaSingleton`, `ZKMultiSigValidator`, `ZKMultiSigValidatorFactory`, ERC-8039 adapters | microchain-zk-signers `96a0137` (`pnpm sync-contracts` records solc and a SHA-256 per contract in `test/fixtures/contracts/manifest.json`) |
| Safe | v1.4.1 (EIP-712 hash is the v1.3.0+ domain with `chainId`) — real contracts in `test/integration` |
| Nexus (Biconomy) | 1.2.1 (`lib/nexus` of microchain-zk-signers) — real contracts in `test/integration` |
| ERC-4337 EntryPoint | v0.7 (`0x0000000071727De22E5E9d8BAf0edAc6f37da032` is the default) |

Nexus requires a default validator distinct from the ZK validator an account installs (in production, the K1 validator).

## Proving resources

| Circuit | Witness + proof (8-core laptop) | On-chain verification |
|---|---|---|
| `zk_multi_sig_ecdsa` | ≈ 10 s with the default thread count, ≈ 25 s with one thread; peak memory of the Node process ≈ 300 MB plus the prover process | ≈ 3M gas (`validateUserOp`), hence the 10M default `verificationGasLimit` |
| `zk_multi_sig_ecdsa_private_state_validation` | ≈ 1 s | verified at account creation and on every state-root rotation |

Witness generation for `zk_multi_sig_ecdsa` blocks the Node.js event loop for several seconds. In a server, prove in a worker process or thread so request handling is not stalled.

## Refreshing fixtures

The end-to-end and on-chain tests use stripped copies of the compiled circuits and the Microchain contracts:

```bash
# after recompiling circuits / contracts
pnpm sync-circuits ../zk-smart-account-kit/noir/target ../microchain-zk-signers/noir/target
OUT="$(mktemp -d)"   # private directory, not a predictable shared path
(cd ../microchain-zk-signers && forge build --out "$OUT/out" --cache-path "$OUT/cache")
pnpm sync-contracts "$OUT/out"
pnpm test
```

`manifest.json` in each fixture directory records versions and a SHA-256 per artifact, so changes are visible in review. The integration tests build Safe, Nexus and the EntryPoint from source instead (`pnpm build-integration-contracts`), because third-party bytecode is not vendored.
